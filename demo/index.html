How each block works IN THE RTL

prbs_gen.v

A 9-bit Fibonacci LFSR, x⁹ + x⁵ + 1, seeded with 1 (all-zeros would lock up). It advances only on bit_req, so it makes one bit per payload bit. The output is the feedback bit. The same sequence is produced bit-for-bit in C, MATLAB, Python and this Verilog; the period is 511.

manchester_enc.v

Runs on the half-bit clock. On ph=0 it samples din into held and sends it; on ph=1 it sends ~held. Every bit therefore has a mid-bit transition: the code is DC-free, which a capacitively coupled body channel needs. The output is registered, so it appears one cycle after bit_req.

channel (testbench)

hb_rx = hb_tx ^ err_inject. Injection lives outside link_top, so the design stays synthesisable. err_inject comes from $random. An earlier LFSR-based injector made hits on neighbouring cycles correlated; two hits in one symbol cancel, so that version reported too few violations.

manchester_dec.v

Stores the first half in h1. On the second half it outputs h1 as the bit and raises viol if both halves are equal. A hit on the first half flips the bit; a hit on the second half only raises a violation. Alignment is assumed, not recovered: the decoder must start on a symbol boundary.

en_d (link_top.v)

The encoder's output is registered, so the first half-bit appears one cycle after en. If the decoder starts at the same time, it pairs the second half of bit k with the first half of bit k+1, and about 50 % of symbols are flagged. Delaying its enable by one flop fixes this. Tick the bug box above to see it.

prbs_check.v

It shifts the received bit into its own LFSR and compares each new bit with lfsr[8] ^ lfsr[4]. After 9 bits the register holds only received data, so it locks wherever the stream started. One flipped bit is counted 3 times (taps + 1): once when compared, then once at each of the two taps.

Clocks and CDC in a real two-chip link NOT IN THIS RTL · NEXT STEP

In this project, TX and RX share clk and the testbench loops hb_tx straight back to hb_rx. The receiver therefore knows the phase exactly, and one en_d flop is enough to align it. Real transmitter and receiver chips each have their own crystal. Tick Real-chip clock view to see where the crossings would go. The pink parts are design notes; the simulation above does not model them.

Two oscillators

tx_clk and rx_clk are a few ppm apart, so the RX sampling point slowly slides across the incoming half-bits. Without tracking, it eventually samples on a transition.

2-FF synchronizer on hb_rx

The incoming line is asynchronous to rx_clk, so the first flop can go metastable when an edge lands in its setup/hold window. A second flop gives it a cycle to settle before anything uses the value.

CDR / oversampling

Sample hb_rx at 4× the half-bit rate. Manchester guarantees a mid-bit edge in every bit, so the receiver can find that edge, choose the sample phase away from it, and re-align continuously. This replaces the fixed en_d and is listed in the README's extensions.

Reset synchronizers

Each domain asserts reset asynchronously and releases it synchronously to its own clock, so no flop sees rst_n rise close to its clock edge.

Readout crossing

For the CPU, err_cnt/bit_cnt cross to sys_clk through Gray-coded counters or an async FIFO; a binary counter must never be synchronised bit by bit. The single-bit locked goes through a 2-FF synchronizer.

rx_clk / tx_clk setup+hold window
Toy timing model, not simulated from the RTL and not real silicon numbers. Shaded = an edge of async_in fell inside rx_clk's setup/hold window, so FF1 goes metastable and resolves after a random time. FF2 samples one rx_clk later and is clean whenever FF1 settles within a period. That is why MTBF grows as etr/τ with the time allowed to settle.
